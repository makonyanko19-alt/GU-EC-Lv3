## 3. 確認手順上の注意

Windowsでは、ターミナルを閉じただけでは uvicorn が終了せず、ポート8000を使い続けることがある。
この状態で環境変数を変えて起動し直すと、新しいBackendはポートを使えず、画面は古いBackendとやり取りする。
今回の確認でも、残っていたBackendが応答し、設定した決済結果にならない注文が2件できた（GU20260921-278591、GU20260921-480237）。
いずれも設定前の結果として正しく処理されており、上表の判定には使っていない。

起動し直す前に、次の手順で残っているBackendを止めてから確認する。

```powershell
# uvicornと、その子プロセスをまとめて止める
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object { $_.CommandLine -match "uvicorn|multiprocessing" } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force -ErrorAction SilentlyContinue }
# 何も表示されなければ、ポート8000は空いている
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue | Select-Object OwningProcess
```

Frontendも同様に、前回の `next dev` が残っていると新しい起動は別ポート（3001）へ移って終了する。
表示されたPIDを `taskkill /PID <番号> /F` で止めてから起動し直す。

## 4. 既知の制約（未実装の範囲）

| 対象 | 現在の動作 | 影響 |
| --- | --- | --- |
| 休日データ（business_calendar） | 土日だけを営業日から除外する | 祝日を考慮しない。例：2026-09-21～23の祝日を含む週でも、配送予定日は9/28になる |
| 決済の再試行（O-03） | 失敗後に同じ注文で支払い直せない | 買い直すには、カートへ入れ直して新しい注文にする |
| 結果不明の定期照会 | UNKNOWNの注文は確認中のまま残る | 確保した在庫も解放されない（ケースBの在庫1点） |
| ゲストの注文照会 | 同じブラウザで作った直近の注文だけを照会できる | 複数の注文を続けて照会できない |
| 冪等キー・Webhook | 未実装 | 同じ購入の再送や、事業者からの結果通知に対応しない |
